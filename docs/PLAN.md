# 彩券購買決策調查：網站版計畫書

> 最後更新：2026-11-17
> 專案目的：讓更多人願意填答，盡可能收集到更多有效樣本，供後續經濟學模型分析使用。

---

## 1. 目標與限制

| 項目 | 內容 |
|---|---|
| 目標 | 增加有效樣本數（更多人填、亂填的人更少、更容易分享） |
| 不可更動 | **所有題目的選項文字**（後續經濟學模型要用），與原 Google 表單 v2 一字不差 |
| 可以更動 | 題目呈現方式、題號、說明文字、版面、互動流程、送出後的回饋 |
| 與先前方案的關係 | 這是**獨立的新架構**：不使用 Google 表單、不連動表單，只沿用相同的目的與題目 |

---

## 2. 架構總覽

```
 填答者手機／電腦
        │  開啟網址（可「加入主畫面」變成 App 圖示）
        ▼
 ┌──────────────────────────┐
 │  前端網站（Vercel 託管）    │  ← 原始碼放在 GitHub，push 後自動部署
 │  index.html / css / js    │
 │  ・首頁 + 一題一頁問卷       │
 │  ・送出後：彩券性格 + 統計圖表 │
 └────────────┬─────────────┘
              │ POST 回覆（JSON） / GET ?action=stats
              ▼
 ┌──────────────────────────┐
 │  後端 API（Google Apps Script 網頁應用程式）│
 │  ・驗證答案（選項必須完全吻合）              │
 │  ・寫入試算表                              │
 │  ・回傳匯總統計（不含任何個別回覆）           │
 └────────────┬─────────────┘
              ▼
 ┌──────────────────────────┐
 │  Google 試算表（資料庫）     │
 │  ・responses：每列一份回覆   │
 │  ・codebook：欄位說明        │
 │  ・summary：作答時間摘要      │
 │  ・timing：每題作答秒數        │
 └──────────────────────────┘
```

**為什麼這樣搭：**
- Google 試算表：免費、你熟悉、可直接下載 CSV 跑模型。
- Apps Script：不用架伺服器，免費、自動有 HTTPS；網站只拿得到匯總數字，拿不到個別回覆。
- Vercel + GitHub：網址乾淨、沒有 Google 的灰色警告列、改程式 push 上去就自動更新。

## 4. 資料格式

### 4.1 `responses` 工作表欄位

| 欄位 | 類型 | 說明 |
|---|---|---|
| `timestamp` | 文字 | 伺服器收到回覆的時間（台北時間，yyyy-MM-dd HH:mm:ss） |
| `client_id` | 文字 | 瀏覽器隨機產生的匿名 ID；同一裝置重複填答時相同，可用來**去重** |
| `duration_sec` | 數字 | 從按「開始作答」到送出的秒數，可用來**排除亂填的超快作答** |
| `source` | 文字 | `web` = 真實回覆；`test` = 測試資料 |
| `version` | 文字 | 問卷版本（目前 `web-1.0`） |
| `Q1_1` | 單選 | 1-1 方案選擇 |
| `Q1_2` | 數字 | 1-2 願付價格（元） |
| `Q2_1` | 單選 | 2-1 方案選擇 |
| `Q2_2` | 數字 | 2-2 願付價格（元） |
| `Q3_1` | 單選 | 3-1 期別選擇 |
| `Q3_2` | 數字 | 3-2 願付價格（元） |
| `Q4` | 單選 | 機率感受 |
| `Q5` | 單選 | 確定 vs. 賭局 |
| `Q6` | 單選 | 購買頻率 |
| `Q7` | 單選 | 性別 |
| `Q8` | 單選 | 每月可支配金額 |
| `Q9` | 單選 | 統計／經濟背景 |
| `speed_flag` | 文字 | 作答過快標示：秒數 < 中位數 × 0.5，或 < 30 秒時寫入說明，整列自動變淡紅色；空白 = 正常（門檻可在 Code.gs 最上方調整） |

- 單選題存的是**完整選項文字**（與原表單相同），不是代碼。
- 試算表裡的 `codebook` 工作表列出每個欄位的完整題目與所有選項（執行 `setup()` 時自動產生）。

### 4.1b `timing` 工作表（每題作答秒數，與 responses 分開放）

| 欄位 | 說明 |
|---|---|
| `timestamp`、`client_id` | 對應鍵：與 responses 分頁同一份回覆完全相同，用這兩欄合併 |
| `source` | web / test |
| `back_count` | 作答過程中按「上一題」的次數 |
| `input_errors` | 金額題輸入被擋下的次數（格式錯誤或超過 1,000,000 元上限），大於 0 可能代表不認真作答（web-1.2 起） |
| `T_Q1_1` … `T_Q9` | 停留在該題的總秒數（小數一位；回頭修改會累加）。空白 = 沒看到這題（選「不想買」後自動跳過的金額題） |

- 黃底規則：每一題各自和「所有人在這一題的中位數」比較，低於中位數 × 0.3（該題滿 10 筆才套用）或低於 1 秒就標黃。門檻在 Code.gs 的 `TIMING_RATIO`、`TIMING_MIN_SEC`、`TIMING_MIN_SAMPLE`，改了之後下次有回覆或重新標示時自動生效。
- `summary` 分頁下方列出各題的中位數與黃底門檻。
- 從問卷版本 `web-1.1` 開始記錄；更早的回覆在 timing 分頁沒有資料。
- `prepare_data.R` 裡有一段註解掉的程式，可直接合併 timing.csv。

### 4.1c 匯入的表單版資料（source = form）

- 選單「🎰 彩券問卷 → 匯入表單版資料（放在最上面）」：讀取 Google 表單回覆試算表，轉換後插入 responses 分頁第 2 列起。
- 自動處理：欄位依位置對應並檢查題號；時間統一格式；`client_id` 依序為 `form-001`…；`source` = `version` = `form`；選項文字只差全形半形或空白時自動校正，完全對不上就略過；選「不想買」卻填金額改為 0；12 題答案完全相同者保留但標記「疑似重複」。
- 每次匯入會先移除舊的 form 資料再重新匯入，不會變兩份；紀錄寫在 `import_log` 分頁。
- 「移除表單版資料」可一鍵撤銷，網站資料不受影響。表單版沒有作答秒數，不參與過快標示，也沒有 timing 資料。
- 分析時 `prepare_data.R` 會保留 web 與 form，並輸出 `source` 欄，建議放進模型當虛擬變數。

### 4.2 分析前的建議清理步驟

1. 篩掉 `source = test`。
2. 同一個 `client_id` 有多筆時只留第一筆（正常情況下網站已擋重複填答，這是保險）。
3. 排除 `speed_flag` 有內容的列（作答過快）。每次有新回覆都會依最新中位數重新計算；也可從試算表選單「🎰 彩券問卷 → 重新標示作答過快」手動重算。
4. 願付價格選「不想買」時網站自動記為 0，與原表單「若都不想買請填 0」的意義相同。

### 4.3 與原 Google 表單資料的差異

- 欄位名稱改成代碼（`Q1_1`…），選項文字完全相同。
- 多了 `client_id`、`duration_sec`、`source`、`version` 四個中繼欄位。
- 若之後要合併表單與網站兩邊的資料，只需把表單的欄位名稱對應到代碼即可。

## 5. 網站功能與設計決策

| 功能 | 做法 | 為什麼 |
|---|---|---|
| 首頁 | 吸睛標題、題數與時間、「已有 N 人參與」、作答說明、開始按鈕 | 降低開始作答的門檻；人數是社會認同 |
| 一題一頁 | 進度條、選完自動跳下一題、可回上一題 | 手機上像做測驗，完成率較高 |
| 自動跳過金額題 | 1-1／2-1／3-1 選「不想買」時，下一題願付價格自動為 0 並跳過 | 少一步；也避免「選不想買卻填正數」的矛盾資料 |
| 數字驗證 | 只接受 0～1,000,000 的數字，可自動去掉逗號與「元」；超過上限當場提醒（網站 `MAX_WTP` 與後端相同） | 減少作廢樣本 |
| 統計圖表鎖定 | 作答前首頁只顯示鎖頭，送出後才解鎖 | **避免受訪者先看到別人的答案而改變作答**（從眾、錨定效應） |
| 彩券性格 | 夢想家／平衡派／精算師／冷眼旁觀者 | 給填答者「結果」，提高分享意願 |
| 你 vs 大家 | 每題長條圖標出「你」的選項；願付價格顯示分布與中位數 | 好奇心與分享素材 |
| 期望值解說 | 結果頁每題下方的 💡 說明（可關閉） | 讓人覺得有學到東西 |
| 分享 | 手機原生分享、LINE、複製連結；分享文字帶上性格類型 | 滾雪球擴散 |
| 防重複 | 同一裝置填過後只顯示結果頁 | 降低重複填答 |
| 防機器人 | 隱藏的陷阱欄位，被填就不寫入 | API 是公開的，擋掉簡單的機器人 |
| 示範模式 | `API_URL` 留空時，送出不寫入、統計用假資料 | 沒接後端也能預覽、測試畫面 |
| 匿名 | 不收姓名、信箱；後端只回傳匯總數字 | 降低填答顧慮，也保護資料 |

### 圖表設計
- 單一數列的橫向長條圖：其他選項是藍色 `#4f73b3`，「你的選擇」是紅色 `#c8412b`，**再加上「你」的標籤**，不只靠顏色辨識。這組配色已用色盲模擬檢查過，可以區分。
- 每列都直接標出百分比；滑過或點選時顯示人數。
- 圖表全部用 HTML/CSS 畫，不依賴外部套件，載入快。

## 6. 網站設定（`js/config.js`）

| 設定 | 預設 | 說明 |
|---|---|---|
| `API_URL` | `''` | Apps Script 部署網址（結尾 `/exec`）。留空 = 示範模式 |
| `SHOW_INSIGHTS` | `true` | 結果頁是否顯示期望值解說 |
| `STATS_PUBLIC_BEFORE_SUBMIT` | `false` | 未作答者能否看到統計圖表（建議維持 `false`） |
| `ONE_RESPONSE_PER_DEVICE` | `true` | 同裝置只能填一次（自己測試時改 `false`） |

## 7. 部署步驟

### 7.1 Google 試算表 + 後端 API
1. 建立一份新的 Google 試算表（例如命名為「彩券問卷資料庫」）。
2. 選「擴充功能 → Apps Script」，刪掉預設內容，貼上 `apps-script/Code.gs`，**按 Ctrl+S（Mac：⌘+S）或工具列的磁碟圖示存檔**。沒存檔的話，上方的函式選單會是空的、點不開。
3. 初始化工作表（以下三種方式擇一，結果都一樣）：
   - **方式 A（推薦）**：回到試算表分頁，重新整理頁面，上方選單列會多出「🎰 彩券問卷」→ 點「① 初始化工作表」→ 依提示授權。
   - 方式 B：在 Apps Script 編輯器上方的函式選單選 `setup` → 按「執行」。
   - 方式 C：什麼都不做，直接進行第 4 步部署；第一份回覆送進來時會自動初始化。
   完成後試算表會出現 `responses` 與 `codebook` 兩個工作表。
   > 函式選單點不開的常見原因：① 還沒存檔；② 用手機或平板開編輯器（請改用電腦）；③ 貼上的程式碼不完整，存檔時上方會出現紅色錯誤訊息，請整份重新複製貼上。
4. 「部署 → 新增部署作業」，類型選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
5. 按「部署」，複製網址（結尾是 `/exec`），這就是 `API_URL`。
6. 驗證：在瀏覽器打開 `API_URL?action=stats`，看到 JSON（`"ok":true`）就成功了。
7. **之後修改 Code.gs**：到「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」。網址不會變，但不做這步，修改不會生效。

### 7.2 建立 GitHub repo
1. 登入 GitHub，按右上角「+ → New repository」。
2. 名稱例如 `lottery-survey`，Public 或 Private 皆可，**不要**勾選「Add a README」（保持空的 repo）。
3. 建立後，依 7.3 授權 Claude 推送程式碼，或自行上傳本資料夾的所有檔案。

### 7.3 授權 Claude 直接編輯 GitHub
1. 在 **claude.ai 的設定**中連結你的 GitHub 帳號（在連接器 Connectors 相關設定裡找 GitHub，實際位置以畫面為準）。
2. 如果 repo 是 **Private**，還要讓 **Claude GitHub App** 能存取這個 repo：在 GitHub 的安裝頁面選「Only select repositories」並勾選 `lottery-survey`。
3. 回到與 Claude 的對話，告訴它 repo 名稱（`你的帳號/lottery-survey`）。連結後在**同一個對話**就會生效，Claude 就能把程式碼推上去，之後也能直接改檔案並 push。
4. 隨時可以在 GitHub 的 Settings → Applications 撤銷授權。

### 7.4 Vercel 部署
1. 到 vercel.com，用 GitHub 帳號登入。
2. 「Add New → Project」，選 `lottery-survey` repo → Import。
3. Framework Preset 選 **Other**，Build Command 與 Output Directory **留空**，按 Deploy。
4. 部署完成會拿到網址（例如 `lottery-survey.vercel.app`），可以在 Settings → Domains 改成好記的名稱。
5. 之後每次 push 到 `main`，Vercel 都會自動重新部署。

### 7.5 接上後端
1. 把 7.1 拿到的網址填進 `js/config.js` 的 `API_URL`。
2. 把 `index.html` 裡 `og:image` 的 `/icons/og-image.png` 改成完整網址（例如 `https://lottery-survey.vercel.app/icons/og-image.png`），LINE／FB 才抓得到預覽圖。
3. Push 上 GitHub，等 Vercel 自動部署完成。

## 8. App 化：加入主畫面

網站已經附上 `manifest.webmanifest` 和各尺寸圖示，加到主畫面後會用 App 圖示、全螢幕開啟（沒有網址列）。

**iPhone（Safari）**
1. 用 Safari 開網站。
2. 按下方「分享」按鈕 →「加入主畫面」→「加入」。
3. 主畫面會出現紅色彩券球圖示，名稱是「彩券直覺」。

**iPhone「捷徑」App（替代方式）**
1. 打開「捷徑」→「+」新增捷徑 → 加入動作「打開 URL」，填上網站網址。
2. 按上方捷徑名稱 →「加入主畫面」→ 點圖示可以換成 `icons/apple-touch-icon.png`（先存到相簿）。
3. 這種方式每次開啟會先跳到捷徑再開 Safari，體驗不如上面的「加入主畫面」，建議優先用 Safari 的方式。

**Android（Chrome）**
1. 用 Chrome 開網站。
2. 右上角「⋮」→「加入主畫面」或「安裝應用程式」。

## 10. 風險與限制

| 風險 | 說明 | 對策 |
|---|---|---|
| 結果頁解說外流 | 填答者截圖期望值解說給還沒填的朋友，等於先看了答案 | 若重視資料純度，把 `SHOW_INSIGHTS` 設為 `false`，只留性格與百分比 |
| 樣本偏誤 | 清大學生修過統計的比例高、可支配所得集中在低區間，變數缺少變異 | 刻意擴散到非理工、非學生族群（家人群組、其他學校） |
| 重複填答 | 換瀏覽器或清除資料就能再填 | `client_id` + `duration_sec` 事後篩選；本來就無法 100% 防止 |
| API 被灌資料 | 後端網址是公開的 | 陷阱欄位、伺服器端嚴格驗證；必要時看 `timestamp` 異常集中的時段 |
| Apps Script 限制 | 免費帳號同時執行數有上限，一般問卷流量不會碰到 | 若短時間湧入大量填答，少數人可能要按「再試一次」 |
| 統計延遲 | 統計有 60 秒快取 | 可在 Code.gs 調整 `STATS_CACHE_SECONDS` |
| 選項被改 | 前後端各有一份題目定義，改錯就會驗證失敗 | **不要改選項文字**；若真要改題目說明，前後端同時改 |
